## 메뉴 구조 조사 (2026-08-18, 실사용 로그인해서 확인)

집사 임대인 대시보드에 실제 로그인해서 메뉴 구성을 우리 것과 비교함. 3단계 구조로 되어있음:

1. **상단 대분류** (캘린더, 세입자/계약관리, 퇴거/공실관리, 분납금/변동관리비, 입금/수납, 계산서/영수증, 월세가계부, 건물/시설, 메모, 공지, 민원, 문자관리) — 클릭하면 그 섹션 기본 화면으로 바로 이동.
2. **좌측 고정 사이드바** — 그 섹션 안 세부 화면 목록이 항상 옆에 붙어있음 (hover 아님, 항상 보임). 예: 세입자/계약관리 → 세입자관리/엑셀일괄등록/만료예정현황/입주예정관리/이전계약현황.
3. **화면 안 탭 줄** — 좌측 항목 안에서 관련 액션들이 또 탭으로 나열 (세입자추가/일괄수정/공실등록/SMS설정/출-호수매칭 등).

**우리(`nav.py`+`base.html`)와 차이점**:
- 우리는 상단 hover 시에만 드롭다운으로 세부 화면이 잠깐 보임 → 집사는 좌측에 항상 고정 표시. hover 방식은 마우스 트래킹 필요해서 클릭 실수 잦음 — 좌측 고정 사이드바가 확실히 더 나은 패턴, 참고할 만함.
- 집사는 상단 바로 밑에 "즐겨찾는 메뉴" 줄이 항상 떠있음 (건물추가/수정, 세입자/공실추가, 간편수납관리, 연체종합관리, 호별납입현황, 건물가계부, 부계정등록, 자동문자설정, 결제설정 — 섹션 안 가리지 않고 항상 노출). 우리는 이런 크로스-섹션 바로가기 바가 없음.
- 집사는 어느 데이터 화면에서든 우측 상단 "건물선택"/"호수선택" 버튼 → 모달 팝업으로 검색·선택. 우리는 화면마다 각자 인라인 드롭다운 필터(화면 이동하면 다시 선택해야 함).
- 집사는 화면 상단에 "총 호수 0 (거주 0 / 공실 0)" 식 현재 상태 요약이 항상 노출됨. 우리는 화면마다 다르고 없는 곳도 많음.

**이미 잘하고 있는 것 확인**: `입금/수납 > 미처리 관리` 화면이 우리 `sukum_import.py`(입금파일 자동반영)이랑 구조가 거의 같음 — 미매칭 입금 목록 + 건별 "신규등록"/"호수변경" 버튼. 우리 설계 방향이 맞았다는 근거. (차이: 집사는 계좌 연동으로 실시간 자동 수집처럼 보이고 우리는 파일 업로드 방식.)

**확인 못 한 것**: 로그인한 계정에 건물이 하나도 등록 안 돼 있어서(빈 계정), 건물/호실을 실제로 트리(계층) 구조로 보여주는지 아니면 평평한 검색 목록인지는 못 봤음. "건물선택" 팝업엔 "더블클릭 시 바로 선택" 안내만 있었고 목록은 비어있었음. 이 계정에 실제 건물 데이터가 있어야 하는데 왜 비어있었는지는 주인이 계정 복구 확인 중 — 복구 끝나면 이어서 확인.
