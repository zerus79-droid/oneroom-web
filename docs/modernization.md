주인의 장기 목표: 인터페이스 현대화.
- 기능/동작 기준점: `C:\Users\someb\Desktop\새 압축\sinbee_n.exe` — "신비 프로그램"/"XP 프로그램"이라고도 부름 (레거시 데스크톱 프로그램, "절대 금지" 규칙(XP 배치 그대로 유지)이 이 파일 기준). **이 컴퓨터에서 실행 안 됨** — XP 설치된 별도 컴퓨터에서만 열리고, 주인이 지금도 그 컴퓨터를 실사용 중. Claude Code는 그 컴퓨터에 접근 불가(데스크톱 GUI 자동화 도구 없음) — 검증 필요하면 주인이 AnyDesk로 원격 접속해서 화면/숫자를 직접 확인해 알려줘야 함.
- 디자인 참고: 집사(zipsa.net) 홈페이지 — 로그인 정보, 대시보드 스냅샷, 메뉴 구조 조사 결과는 전부 `docs/zipsa/README.md`로 옮김.
- **이미 일부 적용됨**: `templates/home.html` + `static/css/style.css`의 `.legacy-home`/`.legacy-title-bar`/`.legacy-user`가 집사 스타일 타이틀바+카드 패널 1차 현대화 결과 (커밋 `bde3687`). 새 화면 현대화할 때 이 패턴부터 참고.
- 화면별로 "레거시 배치 유지 vs 현대화 허용" 범위는 여전히 화면마다 주인과 확인하고 진행 (특히 입주 폼 `.tr-*`는 절대 금지 규칙 그대로 유지).
- **진행 방식 (2026-08-18 확정)**: 지금 있는 파일 구조·틀은 그대로 유지하면서 화면별로 점진적으로 스타일만 입힌다. Flask 라우트 분리 구조, `templates/`+`static/css/style.css` 조합 그대로 — 새 프레임워크·SPA 전환·대규모 재작성 안 함.
- **화면보다 먼저: 내부 뼈대(건물관리) 보강이 우선순위 (2026-08-18)**. 건물 "관리형태" 개념이 빠져있음. 실제 결산 PDF(508-88=책임관리 2018/2026, 1584-8=일반관리 2026, 주인이 파일로 제공)로 검증 완료:
  - **책임관리 (508-88 예시로 검증됨, 2018년부터 2026년까지 8년간 일관됨)**: 세입자가 낸 돈이 **우리 관리사무소 통장**으로 들어옴. PDF의 "입금액" 칼럼은 **월세만**(관리비 제외) — `bd03_det.rent_amt`와 정확히 일치, 관리비(`manage_amt`)는 포함 안 됨. 임대인 정산금(당월지급액) = 입금액(월세분) − 관리수수료 − 수리비 − 중개수수료. **관리비는 애초에 "입금액"에 안 들어가므로 정산 계산에서 뺄 필요가 없음 — 처음부터 우리 몫으로 분리되어 있는 구조가 맞았음** (전 세션에 "관리비가 새고 있다"고 의심했던 건 오해, 정정함). `jungsan.py`의 `is_resp = building.man_cost > 0` 플래그와 `pay_amt = ipkum_tot - man_cost - owner_suri - jungke_cost` 계산식은 **이미 올바름** — 단 `jungsan_det.manage_amt`(호실별 저장값)만 임대료를 잘못 복사해 저장하는 표시 버그가 있음(원본 `sinbee.sql`에도 있던 오래된 XP 데이터 결함, 합계(`jungsan_m.manage_tot`)는 정상).
  - **일반관리 (1584-8 예시로 확인, 현재 웹앱에 전혀 구현 안 됨)**: 세입자가 낸 돈이 **건물주 본인 통장**으로 직접 들어감(우리는 손도 안 댐). 그래서 리포트 구조 자체가 다름 — "입금액"이 월세+관리비 **합산**(둘 다 건물주 계좌로 가니까 나눌 필요 없음), "당월지급액" 개념 없이 대신 우리가 건물주에게 **별도 청구**하는 비용 항목(관리비 정액 + 수리비 + 인터넷 + 옵션비 + 계단청소 + 기타 실비)을 아래에 나열하고 "수익"(=건물주 순수익, 입금액−청구비용)으로 마무리. 호실별 "입금일" 컬럼으로 이번 달 누가 언제 냈는지 추적(책임관리 PDF엔 없음).
  - 원룸은 거의 항상 1건물=1주인이라 관리형태는 건물 단위 속성 (빌라 등 예외 가능성만 있음).
- **`bd01.mgmt_gb` 필드 추가 완료 (2026-08-18)**: `CHAR(1)`, `R`=책임관리 / `G`=일반관리. `building.py`의 `MGMT_OPTIONS`/`_mgmt_label()`, 건물 등록·수정 폼(`building_form.html`)에 노출, 목록/상세 화면에 표시. 기존 6개 건물은 `man_cost>0` 기준으로 자동 backfill 후 **1584-8만 실제 PDF 대조로 G로 수동 수정** — `man_cost>0` 추정이 1584-8에서 틀렸던 게 확인됨(관리수수료 필드가 있어도 일반관리일 수 있음), 그래서 새로 등록/수정하는 건물은 반드시 이 필드로 명시할 것, 자동추정 재사용 금지.
- **입금통장 주체 분리 완료 (2026-08-28)**: `bd01.sukum_acct_gb` (`M`=관리주체 통장, `O`=건물주 통장). 관리형태와 독립 값이다. 현재 자료는 책임관리→M, 일반관리→O로 초기화했지만 책임관리+O 조합도 허용한다. 월정산 지급/청구 방향은 `mgmt_gb`가 아니라 이 값을 기준으로 판단한다.
  - `jungsan.py`의 `is_resp` 판정도 `mgmt_gb`(R/G) 우선 사용으로 전환, 값 없는(옛 미지정) 건물만 `man_cost>0` 추정으로 폴백.
