# XP 정산 로직 참고서

이 문서는 구형 XP 프로그램의 월정산·퇴실정산 동작을 웹으로 옮길 때 보는 참고자료다.
**XP 결과도 무조건 정답은 아니다.** 실제 업무 규칙과 다른 오래된 계산, 잘못 저장된 데이터,
운영 중 생긴 예외가 있을 수 있으므로 아래의 근거 등급과 미확정 항목을 반드시 확인한다.

EXE 전체 함수·SQL·화면 지도와 웹 차이 감사는 먼저 `docs/xp-program-analysis.md`를 본다.

## 근거와 우선순위

1. 주인이 실제 사례와 장부를 보고 확인한 업무 규칙
2. 현재 DB의 수금·입주·퇴실 원자료로 재계산한 결과
3. 여러 장의 XP 출력물에서 반복 확인된 결과
4. XP 실행파일에서 정적으로 확인한 폼·필드·계산 흐름
5. 출력물 한 장이나 필드 이름만 보고 추정한 규칙

서로 충돌하면 위 순서를 우선한다. 한 사례로 일반화하지 말고, 확정되지 않은 계산은 코드와
문서에 `미확정`이라고 남긴다.

## 현재 확보한 원본

- XP 실행파일: `sinbee_n.exe` (2004-03-05, VB6 네이티브 실행파일)
  - SHA-256: `ffc5cda8adf9ec1311d8321d96362db4111369760f9804e79f31c2a86f16e11d`
  - 확인된 심볼: `sJungsan`, `sJungsan_q`, `sBd07_out`, `sBd03_det`,
    `optNapbu_gb`, `txtDache_amt`, `txtOut_jungsan`, `cmdJungsan`, `cmdDache`
  - 심볼 존재만 확인했으며 계산 루틴 전체를 복원한 것은 아니다.
- XP 출력 예시: `sb01_18-09.pdf` (508-88, 2018년 9월 정산서)
  - A4 1쪽, 제목 약 22pt, 본문 약 10.08pt, 표 9pt
  - 하단 항목의 일반 행간은 약 11.3pt
  - 퇴실 예: 후불 양수 `683,333`, 선불 음수 `-145,000`, 관리지시 `퇴실정산`

원본 파일은 현재 저장소 밖에서 전달됐다. 새 AI가 파일을 찾지 못하면 주인에게 다시 받아야 한다.

## 용어와 데이터

- `napbu_gb='A'`: 계약상 선불, 그 외(`B` 등): 계약상 후불
- 실입: `sukum01.su_sil_amt`
- 대체: `sukum01.su_dache_amt`, 임대료 수금성격 `sukum_char='01'`
- 대체 전표: 보통 `sukum_gb='02'`
- 퇴실일: `bd03_det.out_dt`
- 퇴실예정일: `bd03_det.plan_out_dt`
- 현재 입주: `out_dt IS NULL OR out_dt < '1000-01-01'`

## 확정된 표시·합산 규칙

### 일반 수금과 대체

- 월정산 `입금액`에는 임대료의 실입과 임대료 대체분을 표시한다.
- 대체 대상은 임대료뿐이다. 관리비는 대체하지 않는다.
- 대체한 행의 `관리지시`는 `(대체)`로 표시한다.
- 대체는 집주인 대납이므로 세입자 `미수내역`에서는 차감하지 않는다.
- 즉 대체 후에도 세입자 미수는 남고, 집주인 지급 계산에는 임대료 대체분이 들어간다.

### 당월 퇴실 표시

- XP의 `퇴실정산`만으로는 날짜 문의가 반복됐으므로 웹은 `퇴실(mm-dd)`로 표시한다.
- 후불 퇴실 정산액은 양수, 선불 환급액은 음수로 표시한다.
- 관리비는 퇴실 임대료 일할 계산에 포함하지 않는다.

현재 웹에 넣은 **잠정 계산**은 다음과 같다.

- 계약상 후불: `전월 임대료 1개월분 + 당월 입주일부터 퇴실일까지 일할 임대료`
  - 당월 신규 입주자는 전월분을 넣지 않는다.
- 계약상 선불: `퇴실 다음 날부터 월말까지의 미사용 임대료 × -1`
- 거주기간 누적액의 완전한 계약월은 월액 그대로, 마지막 잔여일은 `월액 ÷ 30 × 일수`로 계산한다.
  입주일과 퇴실일은 모두 포함한다. 따라서 2월·31일 달도 완전한 계약월은 월액 1회분이며,
  잔여 15일은 월액의 절반이다.
- 일할 금액은 XP 예시와 맞추기 위해 원 단위에서 버림한다.

이 잠정 계산은 전형적인 선불·후불 사례만 확인한 것이다. 아래 예외 판정 전에는 완성 규칙으로
취급하지 않는다.

## 미확정·필수 검증 항목

### 계약상 후불이지만 실제로 선불처럼 납부하는 세입자

`napbu_gb`만 보면 후불로 잘못 계산된다. 퇴실월 실입금과 누적 납부 위치를 함께 판정해야 한다.

- 퇴실월 임대료가 미입금이면 후불 양수 정산 가능성이 높다.
- 퇴실월 임대료를 이미 선입금했다면 미사용분 음수 환급 가능성이 높다.
- 단순히 퇴실월 입금 한 건만 보고 판단하면 전월분 후납을 선입금으로 오인할 수 있다.

### 계약상 선불의 실입·대체 조합

- 실입 완료: 미사용 기간 환급(`-`)이 원칙으로 보이나 실제 사례 검증 필요
- 실입 없음 + 대체 있음: 환급하면 안 된다. 기존 XP 흐름에는 미사용분을 `청구`로 다루는
  흔적이 있으나 금액·합계 반영 방식은 미확정
- 실입도 대체도 없음: 환급 없음, 미납 유지가 합리적이나 XP 사례 검증 필요

### 미수금

`utils.calc_misu_amt`는 현재 임대료를 과거 전체 기간에 적용한다. 장기 입주자의 과거 임대료
변경을 반영하지 못해 XP/실제 장부와 다를 수 있다. `docs/TODO.md`의 관련 항목도 확인한다.

정적 분석으로 확인한 XP 누적 미수 산식은
`(임대료+관리비)×청구개월수 + 입주자부담수리비 - 종류 구분 없는 누적 실입금`이다.
따라서 XP는 보증금·예치금 실입금까지 월세 미수에서 차감할 수 있다. 웹은 업무상 금액을
분리하기 위해 종류01 월세 실입금만 빼므로, 이 부분은 XP와 의도적으로 다르다.

## 인쇄 배치 참고

- 제목 약 22pt, 본문 11pt(웹 가독성을 위해 XP 10.08pt보다 1pt 큼), 표 9pt
- 본문·하단 행간 `1.15`
- `당월지급액 금액`은 첫 행 가운데에서 한 줄로 표시
- `임대료대체`는 오른쪽 첫 행, `보증금대체`는 오른쪽 셋째 행
- `계` 다음 수리비 상세는 한 행 간격
- 중개수수료 상세는 수리비 상세와 한 행을 띄워 구분한다. 수리비가 없어도 한 행을 띄운다.

## 변경 전 검증 순서

1. 사례의 `napbu_gb`, 입주일, 퇴실일을 확인한다.
2. 해당 월과 전월의 `su_sil_amt`, `su_dache_amt`, `sukum_gb`를 분리한다.
3. 실입·대체·관리비를 섞지 않고 임대료분만 계산한다.
4. XP 출력, 현재 DB 원장, 주인 확인 결과를 나란히 적는다.
5. 최소한 아래 조합을 각각 검증한 뒤 공통 로직을 바꾼다.
   - 후불/미입금, 후불/정상 후납, 후불이지만 선입금
   - 선불/실입, 선불/미입금, 선불/대체
   - 월초·월중·월말 퇴실, 당월 신규 입주 후 퇴실
6. 검증하지 않은 조합은 임의로 확정하지 말고 이 문서의 미확정 항목에 남긴다.
